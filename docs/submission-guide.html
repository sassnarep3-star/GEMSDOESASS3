The one file that fixes the portal error

The error “Predicted values must be in range [0, 1]” is raised by the portal's element-wise range test on the stored cells: NaN compares False against [0, 1], so any file that stores NaN outside the footprint is rejected even when every in-footprint value is legal. gemsdoesass3-lbinv-84262-20261030T0900Z-safe.tif uses the portal-safe encoding instead:

  • every stored cell is finite and in [0, 1] — 0.0 background inside the footprint, 1.0 at each of the 84,262 dots, 0.0 outside;
  • the null-ness of the outside cells is carried by an internal GDAL per-dataset mask band, so rasterio/GDAL read them as nodata;
  • the dot set is bit-identical to the NaN-payload analysis copy (symmetric difference 0).

Reproduce the format check: python scripts/validate_submission_tif.py docs/downloads/gemsdoesass3-lbinv-84262-20261030T0900Z-safe.tif — it exits 0 only when all 11 hard gates pass, including portal_range_test_all_cells.

But format is not enough. The same file fails the lane rule: 99.9% of its dots are within 3 px of the calibration lattice (a registry raster), over the 70% cap. See the executive summary and run card.

Step 1 — Take a cleared file

  1. A file may only be submitted after it passes every programmatic gate: format/range (11 checks), the literal lane rule (≤70% within 3 px of any registry raster, measured at the organizer's 300 m / 3 px kernel radius), and the estimator/canary checks.
  2. Verify the SHA-256 of the .tif against the run card before uploading.
  3. No file in this checkout currently passes all of these, so no submission should be made from it.

Step 2 — Open the submission form

  1. Go to the competition page.
  2. Choose Submit prediction (the page the owner screenshotted calls it New submission).
  3. In File to submit, choose the .tif (or the .zip).

Step 3 — Fill in the two fields

  • Submission name (the “unique name”): a short identifier such as gemsdoesass3-<site>-<method>-<date>.
  • Note (optional) — a short comment ≤140 characters, e.g. the LB-inversion note LB-inversion field: 84262 dots; est 0.369 (LOO sd 0.053) (56 characters).

Step 4 — Check the weekly cap, then submit

  • The official rules allow three submissions per week and one final submission per entity (official rules §3.2).
  • Promotion to a real slot is a separate selector decision. Spending a slot is the owner's call, not an automatic project action.
  • Generative-AI use must be disclosed in the narrative (rules §3.2).
