How to submit to the DOE GEMS Prize Challenge

This page is the exact, human-checkable walkthrough. There is no manual inspection step in the project: every gate that decides whether a file may be submitted is a program that runs on the saved bytes.

⬇ Download the .tif ⬇ Download the .zip

Step 1 — Take the file

  1. Click Download the .tif above. The .zip beside it holds the identical bytes.
  2. Verify the SHA-256 of the .tif against 67ce8163f7cccac4f693946ce6328194abb8627fc2af18f8c26a67b4cac48f79 (run sha256sum on Linux/macOS).
  3. Filename to use: gemsdoesass3-lbinv-84262-20261030T0900Z-safe.tif.

Step 2 — Open the submission form

  1. Go to the competition page.
  2. Choose Submit prediction (the page the owner screenshotted calls it New submission).
  3. In File to submit, choose the .tif (or the .zip).

Step 3 — Fill in the two fields

  • Submission name (the "unique name"): gemsdoesass3-lbinv-84262-20261030T0900Z-safe
  • Note (optional) — a short comment to tell submissions apart: LB-inversion field: 84262 dots; est 0.369 (LOO sd 0.053) (56 characters, under the 140 limit).

Step 4 — Why this file will not hit "Predicted values must be in range [0, 1]"

That error is raised by the portal's element-wise range test on the stored cells: NaN compares False against [0, 1], so any file that stores NaN outside the footprint is rejected even when every in-footprint value is legal. This file uses the portal-safe encoding instead:

  • every stored cell is finite and in [0, 1] — 0.0 background inside the footprint, 1.0 at each of the 84,262 dots, 0.0 outside;
  • the null-ness of the outside cells is carried by an internal GDAL per-dataset mask band, so rasterio/GDAL read them as nodata;
  • the dot set is bit-identical to the NaN-payload analysis copy (symmetric difference 0), so the estimate and uniqueness receipts apply unchanged.

Reproduce the check: python scripts/validate_submission_tif.py docs/downloads/gemsdoesass3-lbinv-84262-20261030T0900Z-safe.tif — it exits 0 only when all 11 hard gates pass, including portal_range_test_all_cells.

Step 5 — Check the weekly cap, then submit

  • The official rules allow three submissions per week and one final submission per entity (official rules §3.2).
  • Promotion to a real slot is a separate selector decision. This file is cleared by every programmatic gate this project runs; spending a slot is the owner's call.
  • Generative-AI use must be disclosed in the narrative (rules §3.2).
