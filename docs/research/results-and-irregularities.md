## The nine sites and H33

The highest *user-reported value* among those nine is associated with GEMSDOE32 H33-B2. It is **not ORGANIZER-CONFIRMED**: [its own audit](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/1398109a23f04a2ace71c1bd2f527cfba87860b5/docs/downloads/gemsdoe32-h33-h33-2-b2-20261004T220000Z-e5eb6e7e-audit.json) calls it `UNSCORED`; a submission-page receipt tying that exact SHA to a score has not been found. The user's number may reflect a later unrecorded submission; absence of a receipt does not prove that no submission occurred. It does mean the score/file attribution is unverified. The public leaderboard does not establish which TIFF any participant uploaded.

We verified the following raster geometry ourselves: the H33-B2 support is exactly the GEMSDOE31 H27 support with **2,545 pixels removed and no pixels added**. All removed pixels are within two pixels of the mirrored catalogue, and H33 has no positive pixels within that collar. This establishes lineage, not a causal leaderboard result.

A plausible—but unproven—explanation for a gain is that removing low-value predicted mass reduces false-positive cost while preserving much of the kernel coverage. Conversely, the [organizer explicitly says](https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/4) a *new* truth pixel can lie within 300 m of an old trace. Thus the collar may also remove valuable predictions; there is no universal reason to prune it. Sparse coverage can reduce redundant prediction mass, but spatial arrangement and false-negative cost matter.

The [official metric](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/) is `TPw / (TPw + 0.2 FPw + 0.8 FNw)`, using the 300 m triangular kernel and `FNw = |G| − TPw`. Importantly, `TPw` sums over **truth pixels**, while the credited part of `FPw` sums over **predictions**: they are not generally interchangeable. Neither hidden fault prevalence nor per-dot truth credit is identifiable from a few reported leaderboard values. Consequently we cannot honestly estimate this candidate's organizer score or promise it will exceed a historical claim or the public leader.

The [official public leaderboard](https://www.drivendata.org/competitions/306/competition-doe-gems/leaderboard/) showed **0.4544** for first place when observed on 2026-10-27 UTC. This is an **OFFICIAL PUBLIC LEADERBOARD OBSERVATION**, not a submission-page receipt for our TIFF and not a private/final score. It may change. DrivenData's [Terms of Use](https://www.drivendata.org/termsofuse/) prohibit automated website monitoring; we do not run a leaderboard scraper. The site links directly to the official page instead. ## One bounded experiment: H1 shifted magnetic texture

[Pre-registration and alternatives](preregistration-2026-10-27.md) precede the implementation. H1 compares locally averaged RTP magnetic patch differences across candidate orientations with and without tangential offsets, then gates that advantage by a directional detrended-elevation break. The intent is to test for displaced buried magnetic markers, not to identify vents directly. No catalogue-derived feature is used. USGS describes [fault-related aeromagnetic expression](https://www.usgs.gov/publications/aeromagnetic-expression-faults-offset-basin-fill-albuquerque-basin-new-mexico), and also documents [non-fault interpretations of magnetic lineaments](https://pubs.usgs.gov/of/2000/of00-188/of00-188.pdf). A lithologic contact or fluvially reworked magnetic sediment can mimic the feature. These sources motivate the test; they do not establish that this algorithm finds faults.

The shared `gems57.spatial.folds` hides whole connected catalogue components intersecting each fixed spatial quadrant, excludes their tails from training, and uses an 80-pixel training buffer. There is no trained model in this experiment; the deterministic surface never consumes a label-derived input. The shared `gems57.evaluate_holdout` pixel-exactly masks visible faults and pools triangular-kernel components. Spatial-cluster bootstrap intervals are conditional on this split and are **not** uncertainty intervals for an organizer score.

3. **Mirror provenance and sample discrepancy.** We verified hashes, grid, and contents, but not organizer origin. The mirror's sample contains 60,988 nonzero cells, identical to the mirrored catalogue, whereas the problem page describes a total-absence sample. Do not use its pixel values as independent truth or assume it is an authenticated sample.
4. **Ambiguous `tc` metadata.** The owner mirror describes `tc` as tilt/curvature, whereas separate documentation refers to radiometric total counts. We did not use or interpret this band; resolve against organizer metadata before treating it as radiometry.
5. **Upstream shared prose bug, not used by our run.** `gems57.metric`'s docstring states `ΔTP <= k_self` for a new dot. This is false if the dot credits multiple truth cells. A synthetic dot between two truth pixels has `ΔTP = 4/3` and `k_self = 2/3`; `dti_exact` itself gives the correct values. The simple threshold in that prose requires the special case of a single affected truth pixel. We did not fork or change the shared tool. The connected GitHub identity has no push permission for `57GEMSDOE`; an attempt to file an upstream issue was denied by the GitHub integration. The defect needs correction in the upstream shared template.
6. **No complete registry or prior holdout best.** One witness is enough for a negative result, not a complete clearance. A new lane needs a refreshed, complete accessible registry, surface and final-dot checks, and a same-split prior-best comparison with a paired CI.
7. **No authenticated competition account, organizer receipts, quota, or private labels.** We cannot upload, select a slot, prove portal acceptance, or infer a live score. The official [quota clarification](https://community.drivendata.org/t/submission-amount-question/11553) says the limit displayed by the competition website prevails. External data must be licensed for this challenge and shareable with the sponsor.
8. **No autonomous organizer feed.** The site's automated refresh covers GitHub repository metadata only. A compliant, current organizer feed would require an authorized official API or explicit permission; the official leaderboard link is the live source.
9. **Other repositories.** This checkout can consolidate all nine reviews, but the connected identity does not have push access to most of those repositories. Their individual websites were not modified.
