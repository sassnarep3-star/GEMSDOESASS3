Step by step

  1. Download the .tif (or the .zip, which contains the identical file).
  2. Optional but recommended: confirm the SHA-256 above matches your download.
  3. Open the competition and choose Submit prediction → New submission.
  4. File to submit: choose the downloaded .tif. The portal accepts a single-band GeoTIFF or a .zip holding one GeoTIFF.
  5. Note (optional): paste LB-inversion field: 59542 dots; est 0.371 (LOO sd 0.053) so you can tell this submission apart later.
  6. Submit. The portal validates CRS, shape, geotransform and value range before accepting.

Weekly limit: three submissions per week, one final submission per entity, and any generative-AI use must be disclosed in the narrative (official rules §3.2, §3.4). Check your remaining allowance before you spend a slot.

If you see "Predicted values must be in range [0, 1]"

That error means the file you selected is not the one on this page. This candidate stores only two finite values inside the scored footprint — 0.0 (background) and 1.0 (a dot) — and NaN strictly outside the footprint, exactly as the competition text requires ("data outside the bounds is null or nan"). There is no third value, so the range check cannot fail on this file.

It will fail on older files in this repository that wrote 0 in the no-data region (for example the …-zeros variants) or on any file with values outside [0, 1]. Re-download from this page and re-select it.

Re-validate any file, any time

Every gate is reproducible from the saved bytes — no human judgement is used:

python scripts/validate_lbinv_submission.py --tif docs/downloads/gemsdoesass3-lbinv-59542-20261031T0000Z-nanoutside.tif

It exits 0 only when all 22 gates pass, and it recomputes the headline estimate from the raster rather than trusting a stored number. Receipts: validator · estimator (re-run 2026-10-31) · build receipt.

What this file is not

  • Not an organizer-confirmed score. No per-file leaderboard score is public; every calibration number here is OWNER-REPORT.
  • Not new recall. The field is defined only where a published raster places a dot, so this file redistributes the recall the corpus already has. It is a better-shaped version of the same pattern, not a new discovery.
  • Not a catalogue prediction. Known USGS/INGENIOUS fault pixels are masked out of scoring, so predicting the catalogue earns nothing.
