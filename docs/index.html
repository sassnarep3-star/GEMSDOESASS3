Why the earlier attempt failed, and why this file will not. The form error "Predicted values must be in range [0, 1]" is an element-wise test of every stored cell against [0, 1]; a NaN comparison is False, so the previous NaN-outside raster was rejected even though every finite value was legal. This file stores exactly 0.0 in every background cell (inside and outside the footprint) and declares null-ness through an internal GDAL mask band — the emission (the dots) is unchanged, and every finite value is exactly 0.0 or 1.0. The in-project gate scripts/validate_submission_tif.py runs the same range test the form runs and exits 0 on these bytes; the full receipt is evidence/validator_kernelpack_20261031.json.
