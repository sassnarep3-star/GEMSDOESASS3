This repository currently contains no candidate file and no selector approval. The instructions below explain the general process; they do not authorize a submission or consume a competition slot.

Required file contract

The official challenge page requires a GeoTIFF covering the whole region, with the training data's projected coordinate system (EPSG:32611), 100 m resolution, matching bounds/grid, one 32-bit floating-point band, probabilities/confidence in [0,1], and null/NaN outside the bounds. Use the official sample submission as the grid template. Local validation does not guarantee organizer acceptance.

Safe upload checklist (only when a run is approved)

  1. Open the run's explicit “OK TO SUBMIT” record and confirm it names the exact `.tif` and SHA-256. Research-only downloads are not upload candidates.
  2. Download the single-band GeoTIFF or the permitted ZIP containing exactly one GeoTIFF. Do not rename or alter the file after validation; any change requires revalidation and a new hash.
  3. On the DrivenData competition page, choose the new submission form and select the approved file. Verify the displayed filename before continuing.
  4. Enter the exact run-card submission name and copy its ≤140-character note into the optional note field. Never paste a projected score as a confirmed score.
  5. Review the competition rules and the current weekly allowance in your authenticated account. If the independent selector has not authorized this exact file, cancel rather than submit.
  6. After upload, preserve the organizer's receipt and returned score as `ORGANIZER-CONFIRMED`; bind it to the uploaded file hash if the receipt provides enough information. Do not infer that a local validator pass means the portal accepted it.

Why the range error matters

Every prediction value must be in [0,1]. A single invalid finite value can trigger “Predicted values must be in range [0, 1]”. Validate the reopened written TIFF, not only the in-memory array. Also check the exact CRS, raster dimensions, transform, bounds, band count and dtype. Follow the official outside-footprint null/NaN requirement; do not assume zero-valued outside cells are equivalent.
